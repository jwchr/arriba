# Handoff: current state

Updated 2026-11-01 (route 165 printed timetable added). Keep this short; replace stale lines rather than appending.

## Built and tested
- M1 prototype on invented demo data (`src/data/demo.ts`, DEMO banner): home with ordered saved commutes and one-tap reverse, stop search with wrong-side guard, 7-day all-day timetable, departure detail with front-sign, stop list, Port Authority gate card (usual gate), ticket warning, exact-bus lock (scheduled-only until M3), English/Spanish, light/dark, offline service worker.
- Domain logic: GTFS service-day time with DST and after-midnight trips, calendars and holiday exceptions, departures, direction guard, favorites, trip lock state machine, gate parsing/selection/change detection. 63 unit tests (36 domain and GTFS, 19 on the printed route 165 data, 8 running the service worker).
- `scripts/build-gtfs.mjs`: real NJ Transit GTFS zip to `public/data/corridor.json` (corridor routes only); tested on a synthetic mini feed. When that file is present the app uses it instead of the demo. Stop times the feed leaves blank are filled in and listed in `trip.estimated`; the app shows them as `~7:20 AM` with a legend.
- NJ Transit data-terms notices (footer and Settings, English and Spanish): data obtained from NJ Transit and redistributed from Arriba's own server; may not be real time. The demo shows only the real-time line, since its data is invented.
- Offline hardening (OFF-01, issue #5): the service worker revalidates the page and schedule, gives the network 4 seconds, then uses its saved copy and marks it; the app then says "Showing the schedule saved <date, time>" even when the browser thinks it is online. The app shows a loading screen and, if nothing loads in 15 seconds, an error with a retry. The demo loads only with `?demo` or when no dataset is published (404), never as a fallback for a failed load. Offline page loads ignore the query string.
- 11 Playwright flows on a Pixel 7 viewport; four stub the dataset (NJ Transit source line and estimate marker; failed load and retry; saved copy; no dataset published), and three run on the committed route 165 data.
- Route 165 printed timetable (owner-supplied PDF "T0165 - 7/26", issued 7/1/26) is typed in as `data/t0165/transcription.json` and built by `scripts/build-timetable.mjs` into the committed `public/data/corridor.json`, so the app now shows real 165/165T times (500 printed trips: weekday, Saturday, Sunday, both directions). The app shows a "typed in from NJ Transit's printed timetable" banner. NJ Transit's printed Port Authority gate rules (gate change effective 3/15/2025) show as "Gate 212, door 1" etc. with a "general rule, not posted for this bus" note. Printed rider notes shown in the app: the Westwood first-pickup note, and the Exit 165 Park/Ride note (PM Parkway express trips stop there only if the rider asks when boarding), shown when the rider gets off there from a P or FP trip. To rebuild: `npm run timetable -- --built-at <ISO>`; `tests/unit/timetable.test.ts` fails if the committed JSON and the transcription disagree.
- Limits of that data: 20 timepoints per direction only (no intermediate stops, so a rider's own stop may be missing); no coordinates, so the wrong-side guard works only through named twin stops (same printed location both ways, 11 pairs; other map references differ by direction and get no twin); no holiday schedules: the PDF lists 25 holidays but not their times, so on those days (`src/domain/holidays.ts`) the app shows the ordinary times with a "may run a different schedule" warning at the top, in the timetable and on the trip; the end date of the schedule is unknown, so calendars run to 2099-12-31 and the banner is the only warning; headsigns are Arriba's own "route + last timepoint" labels, not sign text; FP trips and F meaning are read from the legend, which defines F and P but not FP; DST edge dates are still unchecked. Transcription method: per-cell OCR with AM (light) / PM (bold) classified from stroke weight, resolved by a monotone-time search per row, structural checks (no step over 45 min, every cell valid), four independent passes compared, about 25 cells corrected by eye, and an 18-row random visual check with no errors found. It is not NJ Transit's feed: replace it with `build-gtfs.mjs` output at M2 and compare the two.
